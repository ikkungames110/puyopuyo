## 「ベスト」の条件

構築中はぷよを消さず、表示された接続確認ツモを置いたときの連鎖数を最大にします。接続確認ツモの配置は自動探索です。構築用ツモの全到達可能配置の組み合わせと、最後の接続確認ツモの全配置を調べ、最大値を固定データに保存しています。同じ最大値に届く別の配置も正解です。

得点・入力数・ちぎり回数は優劣の判定に使いません。これは表示された有限のツモと本シミュレーターの移動規則に対する最適化です。未知のツモへの受け入れ、実戦の安全性、相手への対応、記事中の柔軟性の優先順位を自動評価するものではありません。

## 元図からの加工

記事中の折り返しを数値化し、操作できる安定盤面へ加工しました。元図上空の発火用ツモは盤面に含めません。右側の省略部分は短い独自の土台に置き換え、上部の支えに必要な灰色は実際に消去・落下するおじゃまぷよ（値6）として固定しました。したがって記事図の完全再現ではなく、接続原理を使った派生課題です。

左3列の上面から1〜2組を取り除き、それを構築用ツモにします。取り除く各段階で接続確認ツモだけでは元の連鎖数に届かないことを確認しています。色替え・左右反転を正規化し、既存配置問題と同じ構造の開始盤面を除外しています。記事の全文や画像ファイルは配信しません。

## 再生成・検証

```sh
node scripts/generate-note-drills.mjs
npm test
```

Node.js 24で実行します。参照図URL・転記した列・接続確認ツモは `scripts/research/note-fold-motifs.json`、生成結果は `src/data/note-fold-drills.json` に保存します。`searchAudit` は構築中に消さない全配置手順数、最適手順数、最大連鎖数です。左右対称や同じ最終盤面に至る異なる配置手順を別手順として数えます。

ユニットテストで全手順を再探索し、最大値・全最適解の採点・最大値に届かない誤答を検証します。E2Eテストで記事タグ検索、配置、採点、解答再生、出典リンク、スマホ表示を確認します。
